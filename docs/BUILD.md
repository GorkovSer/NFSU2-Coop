# Сборка из исходников

## Окружение

Windows, Python 3, пакет `pefile`, LLVM-MinGW. Скрипт ожидает компилятор здесь:

```text
work/toolchain/llvm-mingw-20261006-msvcrt-x86_64/bin/i686-w64-mingw32-gcc.exe
```

Поместите соответствующий toolchain в эту папку. Он не включён в репозиторий. `pefile` устанавливается в используемое Python-окружение (`python -m pip install pefile`).

## Production

Из корня репозитория:

```powershell
python work/build-native.py "C:\Games\NFSU2\SPEED2.EXE" --next
python work/package-coop.py --name NFSU2-Coop-local --unverified
```

Входной EXE только читается, проверяется по SHA-256; скрипт не изменяет установленную игру. Выход — `work/native-world-build/`, архив — `work/releases/`.

`--unverified` явно отмечает пакет как непроверенный кандидат. Его нельзя переименовывать в «проверенный» только на основании успешной компиляции.

## Тесты и лаборатория

Исходники автономных проверок сохранены. `work/check-offline-final.py` компилирует и выполняет тестовые программы, но не запускает NFS. Часть проверок ожидает собственный EXE в `work/game-test-coop/SPEED2.EXE`. Последние изменения паузы могут требовать обновления старых ожиданий тестов; зелёный статус для текущего snapshot не заявляется.

Флаг `--next --lab` предназначен для отдельной локальной лаборатории. Не распространяйте лабораторные DLL и LabBoot как обычный релиз.

## Происхождение файлов

`build.json` содержит хеш DLL и отпечаток файлов, доступных во время сборки. Публичный репозиторий — отобранный снимок исходников, без частных аналитических скриптов, дампов и истории локальной лаборатории. Поэтому его `source_sha256` при новой сборке будет отличаться от отпечатка приложенного локального релиза: не выдавайте его за побайтовое воспроизведение опубликованного ZIP.

В `docs/release-artifact.json` сохранены версия и хеши исходного подготовленного пакета. Бинарный пакет прикладывается к Release отдельно от исходников.
